# Электронная таблица с поддержкой формул и графом зависимостей (C++17)

Реализация ядра электронной таблицы с поддержкой арифметических формул, автоматическим пересчетом значений и обработкой циклических зависимостей. Проект демонстрирует применение генераторов парсеров (ANTLR), работу с графами зависимостей и современные идиомы C++ для создания надежного и расширяемого API.

## 🚀 Ключевые особенности и Архитектурные решения

### 🧠 Парсинг формул через ANTLR
Для лексического и синтаксического анализа математических выражений используется генератор парсеров **ANTLR**. Формулы разбираются в Абстрактное Синтаксическое Дерево (AST) через класс `FormulaAST`, что позволяет безопасно и эффективно вычислять выражения произвольной сложности, избегая небезопасного `eval` и ручного написания парсеров.

### 🕸️ Граф зависимостей и защита от циклов
Реализован механизм автоматического отслеживания ссылок между ячейками (`referenced_cells_` и `dependent_cells_`). При изменении формулы граф динамически обновляется, а алгоритм обхода проверяет наличие **циклических зависимостей** (`CircularDependencyException`) на этапе ввода, предотвращая бесконечную рекурсию и падения при вычислениях.

### ⚡ Ленивые вычисления и инвалидация кэша
Вычисление значений формул происходит только при запросе (`GetValue()`). Результаты сохраняются в кэш (`mutable std::optional<Value>`). При изменении зависимых ячеек происходит каскадная **инвалидация кэша** (`InvalidateCache()`), что исключает повторные вычисления неизменных частей таблицы и значительно повышает производительность.

### 🎭 Паттерн State и Pimpl в архитектуре ячеек
Класс `Cell` использует скрытую иерархию реализаций (`EmptyImpl`, `TextImpl`, `FormulaImpl`) через указатель на приватный базовый класс `Impl`. Это избавляет основную логику ячейки от множества условных операторов (switch/if) и изолирует сложные детали реализации формул от публичного интерфейса.

### 🛡️ Type-Safe значения и обработка ошибок
Состояние ячейки описывается через `std::variant<std::string, double, FormulaError>`. Это позволяет возвращать не только числа и текст, но и семантические ошибки вычислений (например, ошибки ссылок `#REF!` или деления на ноль `#DIV/0!`), не прерывая работу всей таблицы необработанными исключениями.

### 🧩 Чистая архитектура на интерфейсах
Строгое разделение через абстрактные классы `SheetInterface`, `CellInterface` и `FormulaInterface`. Внутренняя структура таблицы (`std::unordered_map` с кастомным хэшером `PositionHasher` для пар координат) полностью скрыта от конечного пользователя API, что обеспечивает высокую связность и низкую связанность модулей.

## 🛠 Стек технологий и Навыки

| Категория | Технологии и инструменты |
| --- | --- |
| **Язык** | C++17 (STL, `std::variant`, `std::optional`, `std::unique_ptr`, `std::unordered_map`) |
| **Парсинг** | ANTLR4 (генерация C++ парсера и лексера из `.g4` грамматики) |
| **Архитектура и паттерны** | State, Pimpl Idiom, Factory Method, Observer (неявный через граф зависимостей), RAII |
| **Алгоритмы** | Обход графов (поиск циклов), построение и вычисление AST (Expression Trees) |
| **Сборка** | CMake (интеграция с внешними зависимостями через `FindANTLR.cmake`) |
| **Тестирование** | Unit-тесты (кастомный фреймворк `test_runner`) |
